3. Cenário 

      

        

        

        

        

      

      

        

        

        

      

      

      

      

      

        Como o sistema escolhe o fluxo
        
    
          
  1. Filtro (dbo.FindFlow): serviço, fluxo ativo, FlagEscape e TipoCheckin iguais; cada critério da condição vazio (NULL) ou igual ao do cenário. Campo do cenário vazio = o Controller manda NULL, então só passam condições sem aquele critério.
    2. 
          
  2. Mais específico vence: entre as que passam, ficam as com mais parâmetros preenchidos (Convênio, Primeiro procedimento, Médico, IdadeMin, IdadeMax, TipoProcedimento, TipoConvênio, Ambulatório, Especialidade, TipoAgenda, Agenda). Unidade não conta.
    3. 
          
  3. Check-in com agendamento: entre as mais específicas, primeiro as dentro do LimiteAtraso (atraso < limite; NULL vale 0). Se nenhuma estiver, vale a prioridade entre todas.
    4. 
          
  4. Bloqueio por atraso: depois de escolher, se o check-in já passou do horário do compromisso + LimiteAtraso do fluxo escolhido, o Controller redireciona para o escape LIMIT_DELAY (PosBlockStartFlow).
    5. 
          
  5. Desempate: menor Prioridade, depois o ID do fluxo.
    6. 
          
  6. Sem agendamento, o Controller manda NULL em convênio, médico, especialidade, idades, procedimento e agenda. Idade mín./máx. são do profissional. TipoProcedimento preenchido nunca casa.
